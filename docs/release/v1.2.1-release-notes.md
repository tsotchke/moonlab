# Moonlab v1.2.1 — attributable compute and quantum annealing

Moonlab v1.2.1 is the patch release over v1.2.0. Its two primary
development pillars are attributable seeded control-plane shots and complete
closed-system transverse-field quantum annealing.

It also closes the full post-v1.2.0 integration stream already present on the
release branch: Stim circuit and detector-error-model interchange with Python
QEC/Sinter adapters, verified Clifford decompositions, exact pointwise band
geometry and VQE quantum geometry, custom VQE ansaetze, public-surface
stability tiers, the scoped `@tsotchkecorp` JavaScript packages, and release
pipeline hardening. The changelog is the exhaustive release delta.

## Quantum annealing

- Real statevector evolution of
  `H(s)=-A(s) sum X + B(s)(sum h Z + sum J ZZ + offset)`.
- Symmetric Ising and complete row-major `x^T Q x + offset` QUBO inputs.
- Linear, quadratic, and cosine schedules.
- First-order and symmetric second-order product formulas.
- Explicit or server-assigned non-zero replay seeds and retained samples.
- Exact post-evolution ground energy, representative optimum, degeneracy,
  final classical gap, expected/residual energy, success probability,
  most-likely state, and norm.
- Stable ABI 0.8.0 one-shots plus full Python, Rust, and JavaScript/WASM
  configuration/result parity.
- Independent RK4 dynamics oracle, QUBO/Ising exhaustive parity oracle,
  deterministic replay, hidden-visibility ABI smoke, sanitizer fuzzing,
  runnable example, and scaling benchmark.

The capability is deliberately scoped as the exact logical closed-system
model. Provider-specific topology embedding, thermal bath behavior,
calibration drift, and chain-break handling are not silently approximated.

## Seeded remote shots

- Control protocol v1.1 accepts an optional exact uint64 seed on `SHOTS`.
- The effective seed is passed into execution, returned to the client, and
  recorded in structured request logs.
- Legacy C/Python/Rust/JavaScript result shapes remain compatible; attributed
  APIs retain or verify the seed and fail closed against older peers that
  ignore the token.
- The exact release gate is
  `./scripts/run_seeded_shots_mesh_gate.sh` (default targets `atlas old-donkey`,
  or exactly two targets supplied on the command line or through
  `MOONLAB_SEEDED_SHOTS_TARGETS`).  It builds only
  `seeded_shots_replay_probe` from a clean `git archive HEAD`, runs the probe on
  both targets, and emits a PASS event only after the complete ordered outcome
  lines compare byte-for-byte.  Evidence is written to
  `scripts/icc_traces/moonlab_seeded_shots.jsonl` with the clean source
  fingerprint and target labels.

## Release gate

Publication still requires a clean source tree, current hosted CI, the
v1.2.1 release certificate, the seeded-SHOTS two-host replay, and clean ICC
runtime traces from `run_seeded_shots_local_gate.sh` and
`run_quantum_annealing_gate.sh`. Development tests passing in a dirty worktree
do not satisfy those release-evidence requirements.

The Eshkol v1.3.4 quantum-consumer compatibility proof is produced by
`scripts/run_eshkol_v134_compat_gate.sh`. It archives the published
`v1.3.4-evolve` tag, pinned to commit
`694c31798f3f89d55015492bffd027c01951f7bf` into an ignored Moonlab build run,
builds the CPU-only quantum consumer against the clean Moonlab source, runs all
seven published quantum probes, and emits
`scripts/icc_traces/moonlab_eshkol_compatibility.jsonl` only after explicit
PASS markers are observed for every probe.

## Packaging and regression closure

- Native SDK component archives include the generated pkg-config metadata.
- Linux ABI tests link libm explicitly, and the TSan harness resolves libomp to
  an absolute compiler-provided path.
- A deterministic high-shot regression checks supported noise-instruction and
  measurement marginals against closed-form probabilities.
- All package and runtime version surfaces are 1.2.1; the stable ABI remains
  0.8.0 and the seeded control protocol remains 1.1.
